Using MPI_ANY_SOURCE for rank 0's receive operation yielded identical hit counts and Pi estimates to the original program (Exercise 3) across 1, 2, 4, and 8 processes. This is because the final total is simply the sum of all worker counts, which remains unchanged regardless of the order in which they are added.
The key distinction lies in the arrival order: by using MPI_ANY_SOURCE, rank 0 processes incoming results dynamically as workers finish (for example, receiving in the order 2, 1, 3 for a 4-process job) rather than adhering to a strict sequential order (1, 2, 3). This optimization prevents rank 0 from idling or waiting on a slower, low-numbered worker when faster workers have already completed their tasks.
Performance-wise, execution times remained comparable, with runtime ratios fluctuating between 0.93 and 1.16 compared to Exercise 3, showing no definitive performance advantage. Because each worker transmits only a single integer, the order of reception has a negligible impact on the overall execution time.
